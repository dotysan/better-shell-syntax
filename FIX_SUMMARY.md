# Fix for exec {logfd}>&- Syntax Highlighting Bug

## Problem
Bash supports named file descriptors (available since Bash 4.1) using the syntax:
```bash
exec {varname}>&-
exec {varname}>/path/to/file
exec {varname}<&N
```

However, the syntax highlighter was incorrectly treating the closing brace `}` in `{varname}` as the closing brace of a function block, causing the function to close prematurely.

## Example Bug
```bash
function test_fd {
    exec {logfd}>&-    # Bug: } here closed the function
    echo "Done"        # This appeared outside the function!
}
```

## Solution
Modified the redirection pattern in `main/modified.tmlanguage.json` to recognize named file descriptors.

### Old Pattern
```regex
(?<![<>])(&>|\d*>&\d*|\d*(>>|>|<)|\d*<&|\d*<>)(?![<>])
```

This only matched numeric file descriptors like `9>&2`.

### New Pattern
```regex
(?<![<>])(&>|(?:\d+|\{[a-zA-Z_][a-zA-Z0-9_]*\})(?:>&\d+|>&-|<&\d+|<&-|>>|>|<(?!\()|<>)|\d*>&\d*|\d*(>>|>|<)|\d*<&|\d*<>)(?![<>])
```

The key addition is: `(?:\d+|\{[a-zA-Z_][a-zA-Z0-9_]*\})`

This matches EITHER:
- Numeric FD: `\d+` (e.g., 9, 10, 123)
- Named FD: `\{[a-zA-Z_][a-zA-Z0-9_]*\}` (e.g., {logfd}, {fd1})

## Files Changed
1. `main/modified.tmlanguage.json` - Source pattern definition
2. `autogenerated/shell.tmLanguage.json` - Generated grammar file

## Test Coverage
All patterns verified to work:
- ✓ `{logfd}>&-` - Close named FD
- ✓ `{fd1}>/tmp/file` - Redirect named FD to file
- ✓ `{fd2}<&3` - Duplicate input FD
- ✓ `{myfd}>&2` - Redirect to stderr
- ✓ `9>&2` - Numeric FD (backward compatible)
- ✓ `>&2` - Simple redirect (backward compatible)

## Backward Compatibility
No regressions - all existing test specs pass unchanged.

## How It Works
The redirection pattern now matches the ENTIRE `{varname}>&-` construct as a single unit. This prevents the `}` from being interpreted as a standalone closing brace that would trigger the function's end condition `(?<=\}|\))`.
